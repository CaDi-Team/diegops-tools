# Vault Commands — Design Spec

## Summary

Add a `diegops vault` command group that pulls secrets from HashiCorp Vault (KV v2) and writes `.env` files into local repository directories. Mirrors the `diegops repo` command surface: `init`, `apply`, `list`, `list-diff`.

## Config file

**Default location:** `~/.diegops/repo-vault.yaml`
**Override:** `--config <path>` or `$DIEGOPS_VAULT_CONFIG`

```yaml
targets:
  - path: $HOME/github/org/my-app
    secrets:
      - vault_path: secret/my-app/database
        keys:
          - password
          - username
      - vault_path: secret/my-app/api
        keys: "*"
```

**Note:** `vault_path` uses the *logical* Vault path (e.g. `secret/my-app/database`), not the API path. The tool passes it directly to `vault kv get`, which handles the `/data/` segment internally.

### Field definitions

| Field | Type | Description |
|-------|------|-------------|
| `targets[].path` | string | Local directory path. `$HOME` expanded at runtime. |
| `targets[].secrets[].vault_path` | string | Logical Vault KV v2 path (e.g. `secret/my-app/db`) — no `/data/` segment |
| `targets[].secrets[].keys` | list or `"*"` | Specific key names, or `"*"` for all keys at that path |

### `keys` field deserialization

The `keys` field accepts either a list of strings or the string `"*"`. Modeled as a serde `#[serde(untagged)]` enum:

```rust
enum KeySelector {
    All(String),       // matches "*"
    List(Vec<String>), // matches ["password", "username"]
}
```

The `All` variant is validated at runtime to ensure the string is exactly `"*"`.

### Key-to-env-var mapping

- Explicit keys: written as-is (case-preserved) — Vault key `database_url` becomes env var `database_url`
- Wildcard `"*"`: all keys from the Vault path written as-is (case-preserved)
- Duplicate keys across multiple `secrets[]` entries: last-write-wins (entries processed in order)

## Commands

### `diegops vault init`

- Creates `~/.diegops/repo-vault.yaml` with a commented sample config
- Idempotent: silently succeeds if file already exists
- Creates `~/.diegops/` directory if missing

### `diegops vault apply [--path PREFIX] [--config FILE]`

1. **Pre-flight checks:**
   - Verify `vault` binary on `$PATH` — error if missing
   - Verify `VAULT_ADDR` is set — error if not
   - Verify `vault token lookup` succeeds — error if not authenticated
   - Pre-flight failures are fatal (exit immediately, no partial work)
2. **For each target** (filtered by `--path` if given):
   - Expand `$HOME` in path
   - Target directory must exist — error if missing (unlike `repo apply`, we don't create empty dirs just for a `.env`)
   - For each secret entry, run: `vault kv get -format=json <vault_path>`
   - Parse JSON response, extract keys from `.data.data`
   - If `keys: "*"` — take all key-value pairs
   - If `keys: [list]` — take only listed keys; error if a key is missing (show available keys)
3. **Write `.env`** (content-aware overwrite):
   - Header: `# Generated by diegops vault apply — do not edit`
   - One `KEY="VALUE"` per line — values always double-quoted, with `"` and `\` escaped
   - If generated content matches existing `.env`, skip write and report SKIP
   - File written only if secrets were successfully retrieved for this target
   - On Unix: file written with mode `0600` (`#[cfg(unix)]`)
4. **Update `.gitignore`:**
   - If `.gitignore` exists in target dir: check for exact line `.env` — append if not present (ensure preceding newline)
   - If `.gitignore` does not exist: create it with `.env\n`
5. **Output:**
   - Progress per target (WRITE/SKIP/FAIL) → stderr
   - Final summary (written count, skipped count, failed count) → stdout
   - Exit 0 if all succeeded; exit 1 if any errors (consistent with `repo apply` and `main()` `?` propagation)

### `diegops vault list [--config FILE]`

- Shows targets that already have a `.env` file in their directory
- Output format matches `diegops repo list`

### `diegops vault list-diff [--config FILE]`

- Shows targets in config whose directory does not have a `.env` file
- Output format matches `diegops repo list-diff`

## Error messages

| Condition | Message |
|-----------|---------|
| `vault` not on PATH | `error: vault CLI not found on PATH. Install it from https://developer.hashicorp.com/vault/install` |
| `VAULT_ADDR` not set | `error: VAULT_ADDR is not set. Export it or configure your Vault client` |
| Not authenticated | `error: vault is not authenticated. Run 'vault login' first` |
| Permission denied | `error: access denied for '<vault_path>'. Check your Vault policies` |
| Path not found | `error: secret not found at '<vault_path>'. Verify the path exists in Vault` |
| Key missing | `error: key '<key>' not found at '<vault_path>'. Available keys: [k1, k2, ...]` |
| Target dir missing | `error: target directory '<path>' does not exist. Clone the repo first` |

Per-target errors are collected; apply continues to remaining targets. Exit 1 on any failure (consistent with `repo apply` and `main()` `?` propagation).

## Implementation

### Files to create/modify

| File | Change |
|------|--------|
| `src/commands/vault.rs` | New module — all vault logic |
| `src/commands/common.rs` | New module — extract `expand_home()`, `home_dir()` from `repo.rs` |
| `src/commands/mod.rs` | Add `pub mod vault;` and `pub mod common;` |
| `src/commands/repo.rs` | Refactor to use `common::expand_home()` and `common::home_dir()` |
| `src/main.rs` | Add `Vault` variant to `Commands`, dispatch to vault functions |
| `tests/integration_test.rs` | Add `--help` tests for vault subcommands |

### No new dependencies

`serde_json`, `serde`, and `serde_yaml` are already in `Cargo.toml`.

### Vault CLI interaction

- Shell out via `std::process::Command::new("vault")`
- Parse JSON output with `serde_json`
- No Vault client library — keeps dependencies minimal and matches the `git` pattern from `repo.rs`

### .env format

```
# Generated by diegops vault apply — do not edit
database_url="postgres://localhost/mydb"
api_token="sk-1234"
password="value with \"quotes\" and spaces"
```

## Testing

- Integration tests: `vault --help`, `vault init --help`, `vault apply --help` (no network)
- Unit tests: config deserialization, `KeySelector` parsing, env line formatting (quoting/escaping), `.gitignore` append logic, content-aware skip detection
